## Data model

Series data is ordered by time and stored in typed arrays. Every built-in series uses one of
two public shapes:

```ts
interface OhlcData {
  time: number;
  open: number;
  high: number;
  low: number;
  close: number;
  volume?: number;
}

interface LineData {
  time: number;
  value: number;
}
```

Times must be strictly ascending and unique. `update()` may revise the last point or append a
new one.

## Rendering

Wicklib uses a backend-neutral render model with layered rendering:

1. Grid and axes
2. Series geometry
3. Annotations
4. Extension overlays
5. Drawings
6. Crosshair

Canvas2D is the default and reference backend. The hybrid WebGL2 backend renders dense series
geometry in WebGL2 while keeping text, axes, annotations, drawings, overlays, and crosshair on
Canvas2D. Each layer is redrawn independently. The public extension points remain the overlay
and drawing APIs.

## Time scale and price scale

The time scale is index-based. Missing timestamps do not create gaps unless a trading calendar
enables session gaps. The price scale is linear and can auto-scale or be controlled manually.

## Package boundary

- `@wicklib/core` never imports sibling packages.
- Extensions consume the published core entrypoint.
- Pro extensions use the same public APIs as third-party extensions.
- Hosts own licensing decisions; core does not inspect paid entitlements.

## Host ownership

Wicklib is a charting engine, not an application. Hosts own data transport, persistence,
accounts, menus, settings panels, undo/redo, and product-specific UI.
